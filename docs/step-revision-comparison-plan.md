# STEP Revision Comparison — Research and Insights Plan

## 日本語概要

新旧のSTEPを2つ読み込み、変更箇所と寸法差を確認し、レポートを保存できるローカルツールを次の研究テーマとして整理します。Inefficiency Labの「課題から探す」への掲載を見据え、想定する利用者、初期範囲、検証条件、掲載原稿案をまとめました。これは研究計画であり、2ファイルの自動差分判定の実装・評価結果ではありません。英語本文の要約に続いて、日本語で計画と原稿案を示します。

## English Summary

This proposal targets local comparison of two independently imported STEP revisions,
with highlighted changes, measured dimensional differences and a saved review report.
It connects the research to Inefficiency Lab's problem-oriented Insights articles.
The existing v1.1 editor provides import, supported parameter editing and comparison
against the original model; it does not establish arbitrary two-file correspondence.
The document defines a bounded prototype, evidence requirements and draft website
copy. No new comparison results, customer outcomes or production deployment are claimed.

## 研究のゴール

v1.2.0で[独立した新旧STEPの読込・並列表示・全体測定値の比較](cad-revision-comparison.md)を実装しました。以下の初期計画のうち、局所対応付け・変更判定・寸法差・レポート保存・Insights掲載は引き続き今後の段階です。

想定する場面は、設計・加工・生産技術の担当者が、更新されたSTEPを受け取り、前の版とどこが変わったか確認するときです。

目標とする操作は「旧版STEPを開く → 新版STEPを開く → 変更候補と寸法差を確認する → 確認レポートを保存する」です。入力データと形状計算はローカルで扱います。

利用者が判断したいのは、どこが変わったか、どれだけ変わったか、確認できていない範囲がどこかです。部分形状の認識・対応付けは、この判断を支える技術として開発します。

## 現在の実装と追加する研究

基準は研究リポジトリのコミット `4a849f49e0c0dfb4c9b4d62c1971ec9de38f559b` です。

| 項目 | 現在の状態 | この研究で追加する内容 |
| --- | --- | --- |
| STEPの読込 | ローカル編集画面から1つの作業モデルを読込可能 | 旧版・新版を独立して読み込み、比較中に両方を保持 |
| 形状の比較 | 読込時と編集確定後を同じ視点で表示。体積・面積などを比較 | 別々に読み込んだ2ファイルの対応箇所と変更候補を表示 |
| 寸法 | 対応する編集候補のパラメーターを表示・変更 | 対応が確認できた局所形状について、測定寸法の差を表示 |
| 出力 | 確定した形状をSTEP保存。既存APIには診断用HTMLもある | 2ファイルの差分、比較条件、判定保留箇所を含む専用HTMLレポート |
| 検証 | 対応範囲を限定した既存の研究・編集画面の検証 | 別ファイル間の差分検出について独立した評価を実施 |

根拠は[ブラウザ編集画面の対応範囲](cad-browser-editor.md)、[v1の対応範囲](cad-v1-support.md)、[面・辺の対応付け実装](../src/research_notes/shape_correspondence.py)を参照してください。

## 初期版の範囲案

最初は、平面と円筒面を中心とする穴付き板などの単体部品を対象にします。合成した正解付きモデルを、旧版・新版それぞれ別のSTEPへ出力して読み込みます。判定処理には、変更履歴や正解ラベルを渡しません。

| 項目 | 初期版で検証する内容 |
| --- | --- |
| 入力 | 読込可能な単体ソリッド2つ。単位を明示して揃える |
| 位置合わせ | 最初は同じ座標系での比較。位置・向きの違いを含む条件は、対応が確定するまで判定保留にする |
| 変更 | 穴径、穴位置、板厚の変更と、穴の追加・削除 |
| 対応付け | 面の種類・寸法・位置・接続関係から候補を作り、曖昧なものを明示 |
| 表示 | 新旧の並列表示、対応箇所・変更候補の強調、測定値の差 |
| 保存 | 比較図と差分表を含む、外部接続なしで閲覧できるHTMLレポート |

STEPから測る穴径や面間距離は、元CADの設計寸法・公差・設計意図そのものとは区別します。根拠のない寸法や公差は生成しません。形状が一致しても、元CADの拘束や属性まで同一と判断しません。

対応できない形状や複数候補を「変更なし」に置き換えず、未対応・判定保留として表示します。面の番号はファイルごとに変わり得るため、番号の一致を対応の根拠にしません。

## 検証と掲載に必要な証拠

以下は予定する評価条件です。まだ検出率・処理時間・業務削減時間の実測値はありません。

| 評価条件 | 確かめること |
| --- | --- |
| 同じ形状を別のSTEPとして出力 | 記述順やローカルIDの違いを、形状変更として数えない |
| 穴径・位置・板厚を1つずつ変更 | 変更箇所と寸法差が、独立した正解データに合う |
| 穴の追加・削除 | 対応する穴と、新たに増減した穴を区別する |
| 穴を移動し、全体の体積を維持 | 体積の一致だけで「変更なし」と判定しない |
| 同じ穴が繰り返し並ぶ | 根拠が不足する対応を、一つに決めつけない |
| 回転・平行移動、単位の違い | 形状の変更と座標・単位の違いを分けて扱う。未対応条件は保留する |
| 面の分割・結合、微小な誤差 | 同形状を異なる表現で受け取る難しさと、許容差の影響を記録する |
| 未対応面、不正形状、資源上限 | 対象範囲と処理できなかった理由がレポートに残る |

検出できた変更、見逃した変更、誤って検出した変更、判定保留を別々に集計します。寸法誤差、処理時間、入力の面数も記録します。判定保留を除いた精度だけで評価せず、比較できた範囲も示します。

レポートには、新旧ファイルの識別情報とSHA-256、単位、位置合わせ条件、比較許容差、ソフトウェア版、対応箇所、差分、判定保留理由を残します。レポートを保存後にサーバーを終了しても閲覧できることを確認します。

公開用には、再配布可能なSTEPのペア、作成条件または出所・ライセンス、正解データ、実行手順、結果表、比較図、レポート例を揃えます。顧客データや顧客での改善実績として扱いません。

## 学習モデルを検討する位置

まず幾何計算による方式を同じ評価セットで測ります。自動対応付けで残る失敗について、BRepFormerやBrep2Shapeなどの特徴抽出器が改善に役立つか比較します。既存モデルの分類精度を、本研究の部分照合精度として転用しません。

学習・判定基準の調整に使った形状と、最終評価の形状は元部品や派生関係ごとに分けます。同じ元部品から作った新旧ペアが、学習側と評価側へ漏れないようにします。

## Insightsへの掲載案

掲載先は[Inefficiency Lab「課題から探す」](https://inefficiencylab.com/insights/)です。新規記事のURL案は `/insights/step-revision-comparison/` とします。

既存の[STEPの情報取得](https://inefficiencylab.com/insights/step-part-information/)と[CADの寸法変更・組立確認](https://inefficiencylab.com/insights/cad-dimension-change/)に続く、「受け取った新旧データの確認」を扱う記事として配置します。

以下は研究計画としての原稿案です。実装・評価後は、実測結果と比較図を加え、確認できた範囲に合わせて本文を更新します。サイトへの追加・公開はまだ行っていません。

### 記事タイトル案

新旧のSTEPを比較して、設計変更の確認を効率化できる？

### 一覧の紹介文案

更新されたSTEPの、どこが、どれだけ変わったか。穴径・穴位置・板厚などの差をローカルで確認し、レポートへ残す方法を検証する研究計画をご紹介いたします。

### 導入文案

更新された3Dデータを受け取ったとき、前の版と見比べて変更箇所を確認する作業があります。穴の大きさや位置、板厚などを確認し、関係者へ伝える必要があります。

本研究では、新旧のSTEPを2つ読み込み、変更箇所と測定寸法の差を画面で確認し、その結果をレポートとして保存するローカルツールを目標としています。

現在は、対応する形状の寸法変更と、読込時・編集後の比較を行う研究用の基盤があります。次の段階では、別々に受け取った2つのSTEPの対応箇所を調べ、どの変更を検出でき、どの条件で判定が難しくなるかを検証します。

### 記事の構成案

| 順番 | 見出し | 掲載する内容 |
| --- | --- | --- |
| 1 | 新旧データの確認で、何を知りたいか | 想定する作業、確認する寸法、利用者が判断すること |
| 2 | 2つのSTEPを読み込み、変更候補を確認する | 実装後の操作例と、新旧を並べた比較図 |
| 3 | どこが、どれだけ変わったかを表示する | 穴径・穴位置・板厚の差、根拠の面、許容差 |
| 4 | 変わっていない形状と、判定できない形状 | 同形状の別出力、繰り返し形状、面分割などの評価結果 |
| 5 | 確認した結果をレポートに残す | 実際に保存したHTMLレポートと比較条件 |
| 6 | 手元のデータで導入を検討するには | 対象の部品、現在の確認方法、見逃せない変更を整理 |

実験結果は[公開研究](https://inefficiencylab.com/research/)からも参照できる形にし、記事末尾から[CAD・設計自動化](https://inefficiencylab.com/services/cad-automation/)と[相談窓口](https://inefficiencylab.com/contact/)へ案内します。

### 相談への案内文案

新旧の3Dデータの確認に時間がかかっている場合は、現在の確認方法、対象となる部品、特に見落としたくない変更をお聞かせください。お手元のデータで検証する範囲と、結果の確認方法を整理いたします。

## 利用者に確かめること

記事へのアクセス数だけで需要を判断せず、実際の設計・加工担当者に、直近の変更確認作業、発生頻度、所要時間、既存ツールで困る点を確認します。試作を使う前後で、確認にかかる時間と見逃し・誤検出・手動修正の量を測ります。

効果が確認できるまでは、時間削減率や見逃し防止効果を掲載しません。研究の結果と、顧客の業務で確認した効果を分けて記録します。
