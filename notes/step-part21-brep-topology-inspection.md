# STEP Part 21 and B-Rep Topology Inspection

## 日本語概要

この研究ノートは、外部CADデータや幾何kernelに依存せず、合成STEP Part 21 fixtureから面・辺・シェル・立体の関係をどこまで決定論的に読み取れるかを検証します。閉じた四面体は4面・6辺・1シェル・1立体・自由辺0、1面を除いた四面体は3面・6辺・自由辺3として解決されました。6種類のsurface宣言を分類し、未解決参照を`quarantine`、重複entity IDを`reject`にしました。ただし、これは限定構文の位相検査であり、一般的なSTEP適合性、正確な面積・重心・UV範囲・公差、任意ファイルの安全性を保証しません。詳細は以下の英語本文に示します。

---

## English Summary

This study implements a bounded parser for a controlled ISO 10303-21 subset
and resolves selected edge, loop, face, shell, and solid relationships without
a CAD kernel. Six deterministic synthetic fixtures test closed and open
topology, disconnected solids, declared surface families, unresolved
references, and duplicate instance identifiers.

## Research Question

How much face-, edge-, shell-, and solid-level B-Rep structure can be recovered
deterministically from a controlled STEP Part 21 subset without adopting a
geometry kernel, and which claims must remain deferred?

## Background

STEP separates a physical exchange encoding from the product-data schema that
gives entities their meaning. ISO 10303-21 defines the clear-text exchange
structure for data described using EXPRESS. Application protocols such as AP242
define a much broader model for managed model-based 3D engineering.

A B-Rep also separates geometry from topology. A plane or cylinder is a
supporting surface; a face is a bounded, oriented use of a surface. Edges and
wires delimit faces. Faces form shells, and closed shells can bound solids.
Reading a surface declaration is therefore not sufficient to establish a
valid solid.

NIST's STEP File Analyzer demonstrates the value of entity- and attribute-
level tables for inspection. OCCT's STEP documentation separately lists
points, curves, surfaces, vertices, edges, loops, faces, shells, solids, and
assemblies among the exchange concerns handled by a full translator. This
study uses that conceptual separation but does not reproduce a full translator.

## Method

The implementation has two layers:

1. a bounded Part 21 tokenizer and parser for one `HEADER` section and one
   unparameterized `DATA` section containing simple entity instances;
2. a topology resolver for the selected entities used by the controlled
   corpus.

The parser recognizes strings, numbers, references, enumerations, omitted and
derived markers, aggregates, and typed parameters. It enforces explicit limits
for input bytes, entity count, reference count, aggregate nesting, and token
length. Duplicate instance identifiers are rejected. Unsupported complex
entity instances, parameterized data sections, limit excesses, and unresolved
references do not proceed into topology output.

The topology layer follows these relationships:

```text
MANIFOLD_SOLID_BREP
    -> CLOSED_SHELL
        -> ADVANCED_FACE
            -> FACE_OUTER_BOUND / FACE_BOUND
                -> EDGE_LOOP
                    -> ORIENTED_EDGE
                        -> EDGE_CURVE
```

It derives edge-to-face incidence, adjacent face indices, free edges,
nonmanifold edges, shell closure by incidence, and face ownership through
shells and solids. It also reads declared parameters for planes, cylinders,
cones, spheres, tori, and B-spline surfaces where those parameters are present
in the controlled subset.

## Controlled Experiment

All STEP bytes are generated by the experiment code. No company, customer, or
external CAD model is used. The fixed corpus contains:

| Fixture | Changed condition | Expected result |
| --- | --- | --- |
| `closed_tetrahedron` | Four triangular faces share six edges | accept; closed shell and one solid |
| `open_tetrahedron` | One tetrahedron face is omitted | accept; three free edges and no solid |
| `two_closed_solids` | Two disconnected tetrahedra | accept; two shells and two solids |
| `surface_catalog` | Six declared surface families | accept; classify all six families |
| `unresolved_reference` | One edge use targets a missing entity | quarantine |
| `duplicate_entity_id` | One data instance ID is repeated | reject |

Run:

```bash
python experiments/run_step_brep_topology.py
```

Regenerate the committed fixture bytes as well as the result tables:

```bash
python experiments/run_step_brep_topology.py --refresh-fixtures
```

The experiment writes observation, face, edge, shell, solid, and summary CSV
files plus `results/step_brep_topology.png`.

## Results

All six fixtures match their declared outcomes.

| Fixture | Decision | Faces | Edges | Shells | Solids | Free edges |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `closed_tetrahedron` | accept | 4 | 6 | 1 | 1 | 0 |
| `open_tetrahedron` | accept | 3 | 6 | 1 | 0 | 3 |
| `two_closed_solids` | accept | 8 | 12 | 2 | 2 | 0 |
| `surface_catalog` | accept | 6 | 18 | 1 | 0 | 18 |
| `unresolved_reference` | quarantine | 0 | 0 | 0 | 0 | 0 |
| `duplicate_entity_id` | reject | 0 | 0 | 0 | 0 | 0 |

Each closed-tetrahedron face has three boundary edges, zero free edges, three
adjacent faces, one parent shell, and one parent solid. The open tetrahedron's
three exposed edges each have one incident face. The disconnected solids retain
separate shell and face ownership.

The surface catalog records one declared plane, cylinder, cone, sphere, torus,
and B-spline face. The controlled parameters include cylinder radius 2, cone
radius 2 and semi-angle 0.5 radians, sphere radius 3, torus major/minor radii
4 and 1, and B-spline degrees 1 by 1.

## Interpretation

The experiment establishes a useful first boundary: entity relationships alone
can produce an inspectable topology graph and catch some structural defects.
It is already possible to build CSV inventories, adjacency graphs, ownership
queries, and open-boundary diagnostics without rendering the model.

The closed/open comparison also shows why a declared surface type or file
extension is not enough. Closure is a property of how face boundaries reuse
edges. The parser therefore reports both the shell's declared type and the
closure implied by controlled edge incidence.

The fail-closed decisions preserve distinct evidence. A duplicated identifier
makes the instance mapping ambiguous and is rejected as syntax-level input. A
missing referenced entity is syntactically readable but cannot form the
declared relationship, so it is quarantined for analysis.

## Failure Modes

### A surface declaration is treated as an evaluated face

A cylinder radius can be read from a controlled entity, but the trimmed face's
area, UV range, normal field, and validity require more geometry and schema
semantics than this release implements.

### A closed-shell label is trusted without incidence checks

The label expresses file intent. Shared-edge incidence provides separate
evidence. Neither check alone establishes all geometric validity conditions.

### Analysis-local indices are treated as persistent identifiers

Face and edge indices are assigned after sorting controlled entity IDs. A
different exporter, Boolean operation, or healing pass may split, merge,
renumber, or replace topology. These indices are report coordinates, not
persistent design identities.

### A subset parser is presented as STEP conformance

Real files can use other schemas, complex entity instances, multiple data
sections, anchors, external references, signatures, escapes, tessellation,
assemblies, and many geometry variants. Passing these fixtures does not imply
support for those forms.

### Bounded parsing is presented as a security guarantee

Explicit counters reduce uncontrolled work in this implementation. They do not
prove memory safety, complete denial-of-service resistance, safe filesystem
handling, or safe downstream geometry evaluation.

## Practical Guidance

- Keep physical-file parsing, schema interpretation, topology resolution, and
  geometric evaluation as separate stages.
- Preserve STEP entity IDs alongside analysis-local indices for attribution.
- Report declared shell type and derived incidence evidence separately.
- Derive face adjacency through shared edge use rather than geometric
  proximity.
- Treat unsupported or unresolved relationships as explicit decisions, not
  empty geometry.
- Use generated fixtures with independently known topology before testing
  third-party models.
- Introduce a geometry kernel only when exact evaluated properties are needed,
  and record its version, mapping behavior, license, and distribution model.

## Limitations

- The parser implements only the controlled simple-entity subset used by six
  generated files. It is not a complete ISO 10303-21 implementation.
- `AUTOMOTIVE_DESIGN` is recorded as a header identifier but is not validated
  against an EXPRESS schema.
- Complex entity instances, parameterized or multiple data sections, anchors,
  external references, signatures, archives, and non-UTF-8 encodings are not
  supported.
- Only selected topological and surface entities are resolved.
- Curve geometry is classified by entity type but not evaluated.
- Surface declarations are not intersected with trim loops.
- Area, centroid, UV bounds, representative evaluated normals, face tolerance,
  geometric continuity, self-intersection, and exact validity are not computed.
- Names and colors beyond the controlled solid name are not resolved through
  product, representation, styling, or assembly relationships.
- Incidence treats an edge ID reused by faces as a shared edge; it does not
  prove coincident geometry or correct orientation.
- The synthetic catalog uses open triangular bounds on several analytic
  surfaces to test declaration extraction, not geometrically valid analytic
  patches.
- The implementation has no Open CASCADE Technology dependency. It therefore
  does not inherit OCCT's translation, XDE, geometry, or healing capabilities.
- Results are regression evidence for the committed corpus, not claims about
  arbitrary vendor STEP files or production readiness.
