# 寸法線・補助線からの編集可能CAD復元

続報: [実CAD出力のSVG／DXF検証](cad-drawing-exports.md)。以下は自作SVG段階の固定記録。

調査・実験日: 2026-10-22。基点`ccda3bb1199059de29db8d3b313e79a5b5a104a7`。
版数1.17.0上の独立研究であり、既存の業務自動化ロードマップを変更しない。
[初回の専用注記実験](drawing-to-parametric-cad.md)の続報。

**まず結果を見る: [ローカルHTMLレポート](../results/drawing-dimensions/report.html)。**
入力図面、回転可能な3D、復元直後の寸法照合、編集後モデル、再投影、保留理由を確認できる。
[開き方と再現コマンド](../docs/drawing-dimension-lines.md)も用意した。

## Research Question

前回の`W=40`、`X=12 Y=10 DIA=6 THRU`という専用注記を取り除き、
「40」「12」などの寸法値を、矢印・寸法線・補助線の位置から形状へ結び付けられるか。
図面上の数値を読むことと、その数値が何を寸法指定しているかを判断することを分ける。
今回も、不足や矛盾を図形の縮尺から推測して埋めずに保留する。

## Source Review / Method Selection

寸法線、補助線、端末、引出線、寸法値の用語は
[ISO 129-1:2018の公開用語](https://www.iso.org/obp/ui?_escaped_fragment_=iso%3Astd%3Aiso%3A129%3A-1%3Aed-2%3Av1%3Aen)を参考にした。
実CADでは補助線の接続先変更・傾斜・非表示などもあり、
[SOLIDWORKS公式ヘルプ](https://help.solidworks.com/2025/english/SolidWorks/sldworks/c_Dimension_Extension_Lines.htm)と
[端末/引出線の設定](https://help.solidworks.com/2026/english/SolidWorks/sldworks/HIDD_DVE_DIMENSION_LEADERS.htm)にも多様な表記がある。
これらの公開説明を読んだ範囲で、図面規格全文の適合性検査は行っていない。
**今回の図面・パーサーがISO/JISの全表記に準拠・対応するとは主張しない。**

方式は非AIのベクター幾何解析を継続。既存OCCT、完全拘束スケッチ、
フィーチャー再計算、STEP出力、穴の再計測、HLR評価を再利用した。
新しいCADカーネル、GPU依存、OCR、外部AI APIは導入していない。
前回のA/B/C方式比較を実行したわけでもない。

## Controlled Experiment — 今回の入力

自作SVG20入力、うち復元対象8、保留対象12。各2回実行。
矩形板と分離したZ方向丸穴という形状クラス、mm、原点、
三面の役割、第一角法/第三角法は人の前提として維持する。
数値寸法、縮尺、穴の対応先はcontextへ入れない。

| 図面の情報 | 今回どのように取得したか |
|---|---|
| 全体の幅・奥行・厚さ | 両端の三角矢印を幾何から特定し、寸法線と直交補助線、外形への接続を調べる。近傍の数値テキストを対応付ける |
| 穴のX/Y | 左端/下端から穴中心への基準寸法を取得。位置寸法がない場合、円の画面位置から数値を補完しない |
| 穴径と貫通 | 円周へ接続する単一の引出線と、`⌀6 THRU`等の可視テキストを対応付ける。径だけなら貫通を決めない |
| 図形と寸法の整合 | 各ビューの外形寸法から縮尺を求め、円と穴径/位置、隠れ線、冗長寸法、投影配置を照合 |
| 根拠 | 元SVGのテキスト・寸法線・矢印・補助線・円のIDと座標を保存。IDは参照用で、名称の意味や描画順を判定に使わない |

パーサーの実装は[drawing_dimensions.py](../src/research_notes/drawing_dimensions.py)。
矢印は三角形の短辺と等しい長辺から先端を求める。頂点列の先頭を先端と仮定しない。
寸法線端点には直交する補助線を要求し、外形または穴中心と接続することを調べる。
同一直線上の共通補助線は許すが、寸法値と穴の対応が一意でなければ保留する。

寸法値は水平のSVG textとして抽出し、線の中央または引出線終点の限られた近傍と対応付ける。
回転文字、外向き矢印、寸法線の切れ、折れた引出線、連鎖寸法は今回の範囲外。
SVGのグループは人が選んだビューを表すだけで、寸法ごとの型付け・数値属性は与えない。

抽出後は一時的な専用記法SVGへ変換し、前回の検証処理へ渡す。
この中間形式は**プログラムが寸法線から導出した値**であり、入力や正解の隠しデータではない。
保存する出所SHA-256と根拠は元の寸法線SVGに結び付ける。

### 入力と正解の分離

ワーカーへ渡すのはSVGと人のcontext、空の出力先のみ。
コードを実行してSTEPを生成した後、評価側が別フォルダーの設計値・正解STEPを読む。
正解STEPは復元処理を呼ばず、直接のMakeBox/MakeCylinder/Booleanで作成した。
解析体積・面積も別に計算しているが、双方の形状生成と差分計算は同じOCCT。
別カーネルによる独立検証ではない。

復元対象は無孔/1穴/2穴板、第一角法、縮尺変更、ID/描画順の変更、小数寸法。
基本の40×30×8 mmに加え、52.5×37.25×6.5 mm、穴径5.5 mm等の対照を含む。
これらは開発にも用いた合成対照群であり、未知部品のホールドアウトではない。
[入力の由来と固定ハッシュ](../fixtures/drawing-dimensions/README.md)を参照。

| 評価 | 結果 |

| 保留対象12入力×2回 | 12/12で想定した理由と一致。保留対照の誤確定0 |

| 外形の実測最大誤差 | 2.000000023×10⁻⁷ mm（境界ボックスの許容差膨張を含む） |
| 穴径・XY・貫通長の最大誤差 | 0 mm。生成STEPのB-Repを既存認識器で再計測 |
| 体積・表面積と解析式の最大差 | 1.819×10⁻¹¹ mm³ / 1.592×10⁻¹¹ mm² |
| 同一カーネルの体積IoU | 全て1.0、材料の対称差0 mm³ |
| 実際のB-Repの三面再投影 | サンプル上の対称最大残差7.106×10⁻¹⁵ mm |
| 編集後 | 幅+5、厚さ+2、左端穴の径/Xを各+1 mm。16/16で有効。穴寸法差0 mm、体積差最大2.547×10⁻¹¹ mm³ |

閾値は前回と同じく寸法10⁻⁶ mm、解析式との体積/面積差10⁻⁵ mm³/mm²、
体積IoU ≥ 1−10⁻⁸、サンプル再投影残差0.02 mm。
製造公差や実務での合格基準として推奨するものではない。
再投影は可視/隠れ線を合わせた線集合のサンプル距離で、可視性分類や連続曲線全域の一致証明ではない。

### 保留例

| 入力 | 理由コード | 今回分かったこと |
|---|---|---|
| 穴の位置寸法なし | `hole_position_missing` | 図形だけから位置寸法を埋めない |
| 厚さ寸法なし | `dimension_missing` | 3Dを決める寸法不足を返す |
| ビュー間の幅矛盾 | `dimension_conflict` | 冗長な寸法を照合する |
| 寸法線近くに2つの数値 | `dimension_text_ambiguous` | 近い方を無条件に採用しない |
| 補助線欠落 | `extension_missing` | 数値と形状の接続根拠を要求する |
| 投影法誤指定 | `projection_layout_conflict` | 人の指定も図面配置と照合する |
| 穴径と円が不一致 | `annotation_geometry_mismatch` | 注記と図形のどちらかを勝手に優先しない |
| 貫通指定なし | `hole_extent_ambiguous` | 円と隠れ線だけで貫通と確定しない |
| `40 ±0.1` | `unsupported_annotation` | 公差を無視して40へ縮約しない |
| 穴間の連鎖寸法 | `unsupported_dimension_chain` | 連鎖の解法は未実装として返す |
| 引出線が円に接続しない | `leader_target_missing` | 近くの穴へ勝手に割り当てない |
| `R3` | `unsupported_annotation` | 半径から直径への変換は今回未対応 |

これらは意図的に設計した負例。全ての曖昧・不正入力を検出できることの証明ではない。
コード実行と幾何/再投影/編集の評価段階は分けるが、生成子プロセス内部の
Python例外とOCCT例外の完全な自動分類は引き続き未実装。

## HTMLによる結果確認

HTMLは入力図面と実際のB-Rep由来の三角形を埋め込み、ネットワークなしで表示する。
図面は平面/正面/右側面/全体へ切替と拡大、3Dは回転と拡大、編集前後の切替ができる。
寸法変更は保存済みの実験結果を切り替えるもので、ブラウザー内でCADを再計算する機能ではない。
保留例にはモデルを表示せず、理由と次の確認を表示する。
ダウンロード先にはSTEP、Python、JSONを用意した。

ブラウザー検証で、単純な三角形の重心順描画だと貫通穴を塞いで見せる問題があった。
これはCADの寸法/体積検証の失敗と区別し、表示側に深度バッファを入れて修正した。
HTMLは精度判定に用いる形状計算器ではなく、保存済み結果を確認するための表示である。

## Interpretation / Limitations

専用のパラメータ名がなくても、限定された寸法線の接続・値・形状を結び付け、
編集可能な候補を作る経路が成立した。反対に、ただ数値と図形が存在するだけでは
十分でなく、接続先・基準・貫通の根拠が必要だった。

未評価は、実CADエクスポーターのSVG/DXF、画像OCR、スキャン、回転文字、
別種の矢印・端末、折れ線/斜め/切れた補助線、共有穴位置、一般の連鎖寸法、
公差・GD&T、断面/止まり穴、L字・段付き軸、AIとの比較、未知ファミリー、
ネイティブWindows、別カーネルである。
今回のSVG処理は小さい固定文法で、任意のSVGの安全な取り込みを保証するものでもない。

## Documentation / 今後の研究計画

当面のゴールは、**許諾を確認した小さな図面群について、図面→根拠付き候補→
寸法変更→STEP/HTMLまで追試でき、保留と残る人の確認を説明できること**。
最初から任意図面の全自動復元を目標にせず、未使用の図面でも成立する条件を測る。

| 優先 | 次の研究 | 完了時に確かめたいこと |
|---|---|---|
| 1 | 同じ単純部品を実CADからSVG/DXFへ出力して読む | 自作SVGへの依存を切り分ける。パス・回転・レイヤー・寸法エンティティの差を記録 |
| 2 | 実出力で必要だった寸法表記を追加 | 外向き矢印・回転文字・折れた引出線等を少数ずつ。対応範囲外を誤採用しない |
| 3 | 連鎖寸法・共通基準を拘束として解く | 寸法不足、矛盾、複数の解を区別。位置や尺度を根拠なく補わない |
| 4 | 同じ図面をPNG化し、線検出/OCRの非AIまたは既存処理を基準にする | 文字認識と寸法対応の誤りを分離。必要な追加依存・学習データ条件を先に確認 |
| 5 | A: VLM直接生成 / B: 中間モデル / C: ベクター方式を共通入力で比較 | 寸法、保留、編集対象、再試行数、実行時間、実費を揃えて比較。配布条件・モデル入手性を確認してから実施 |
| 6 | L字または段付き軸を1ファミリー追加し、開発と評価を分離 | 知っている板形状以外へ広がるか。派生図面のリークを避ける |
| 7 | 断面図・止まり穴・深さと複数解釈の対照 | 貫通/止まり等を無理に決めず、必要な追加情報を返せるか |
| 8 | 公称寸法、公差、はめあいを別に扱う | 公差付き表記を「正確な単一値」と混同せず、適用範囲を説明できるか |
| 9 | 独立した生成経路/別カーネルと、許諾済みの実図面小群 | 同じカーネル由来の一致と、受領図面への適用を別々に評価 |
| 10 | 未使用図面群で人の確認・訂正も含めた追試 | 復元率だけでなく誤確定、保留、確認時間、編集後の正しさを報告できるか |

この表は独立研究の優先候補であり、既存v1.15〜v1.24の業務ロードマップへ自動統合しない。
