# B-Rep認識・比較の100項目ロードマップ

**旧計画の記録：** 研究ゴールを中小企業向けの導入負担・確認工数の実証へ変更したため、今後の実装順と区切りは[中小企業向けCAD周辺業務の研究計画](sme-cad-automation-roadmap.md)を優先する。以下の100項目とv1.34のゴールは当時の候補として保持し、現行の実装予定とはしない。

作成日：2026-10-19。現行実装はv1.14.0。以下のv1.15.0〜v1.114.0は、開発順を考えるための**100個の候補番号**であり、実装済み機能・納期・100回のリリースを約束するものではない。既存機能でまとめて満たせる項目は統合する。

根拠は[SMLib・SolidCraft・ClassCADのネイティブB-Rep調査](brep-native-recognition-strategy.md)。この文書では新しい外部製品機能を確認したとは主張せず、追加の調査・接続・実装・検証候補を整理する。採用するカーネルや認識器は固定せず、必要な機能と入力型が合う既存APIを先に使う。

## いったんのゴール：v1.34.0

**対象を絞った部品のB-Repをローカルで解析し、どこに何の形状があるか、寸法はいくつか、新旧で何が変わったかを、根拠と判定保留付きで確認・保存できる状態。**

例えば完成時には、「この穴の径は8 mmから10 mmへ変化（+2 mm）」「この長孔は位置が変わった」「この面群は複数の解釈があるので人が確認」と説明できることを目指す。これは将来の表示例であり、今回実測した結果ではない。

最初の対象は穴付き板・ブラケット・単純な加工部品とし、丸穴・直線長孔を必須の特徴にする。ポケット・ボス・丸み・曲げ等は、利用評価で対応を確認できた条件を追加する。全CADの独自形式、全ての加工形状、元の設計意図の復元は受入条件に含めない。

| 確認すること | 一区切りの状態 |
| --- | --- |
| 入力 | 採用したネイティブB-Rep/文書と既存STEP経路を扱える。全入力をSTEPへ再変換する必要がない。3基盤全てへの対応は前提にしない |
| 取得 | 対応する形状について、種類・位置・方向・寸法・参照面を一覧化。履歴から得た値と幾何から推定した値を区別できる |
| 比較 | 対応を確認できた特徴の追加・削除・位置/寸法変更を表示。対称形状等で曖昧なら確定しない |
| 確認・保存 | ローカル画面・Python/CLIから確認し、CSV/JSON・比較レポートを保存できる |
| 検証 | 正解を人が確認した固定データで、誤検出・見逃し・保留・処理時間を別々に測り、対応範囲を説明できる |

v1.19.0でまず「特徴一覧を使える小さな成果」を作り、v1.34.0で「認識・比較・確認・保存の一巡」を区切る。業務で役立つと分かる時点から利用評価を始められる。100項目を全て実装することを利用開始条件にしない。

## 計画の読み方と採否

- **1〜5：直近の実装候補。** 前回の20項目の方針を引き継ぐ。
- **6〜20：一区切りへ向けた候補。** 既存認識・比較の評価結果で統合・優先順位を見直す。
- **21〜100：その先の研究候補。** 形状の種類、困難なデータ、部分形状検索、変更説明、編集支援、業務接続へ広げる。全てが最初のゴールに必要なわけではない。

共通の完了条件は、対象・出力の定義・面の根拠・公差/座標系・成功と保留を確認すること。下表の「できる」は将来の到達目標を示す。実装前に既存APIの対応、入力互換性、ライセンス・実行条件を確認する。

SMLib、SolidCraft、ClassCADを全て抱える共通カーネルを先に作らない。共有するのは特徴・寸法・判定・出所等の結果とし、形状参照は基盤固有のまま保つ。Quiddity等も入力型が適合する経路で評価し、全入力の変換や認識器の移植を必須にしない。

## 100項目の先で目指す状態と、途中で決めること

長期的には、**受領したB-Repに対して、既存の幾何処理と認識を組み合わせ、特徴一覧・部分形状検索・改訂比較・対応可能な編集・業務出力を提供する基盤**を目指す。案件ごとにカーネルや認識器を作り直さず、接続する処理と対象範囲を選べる状態にする。

その方向へ進むかは、最初のv1.34相当の成果で判断できる。「対象部品で有用な情報が取れるか」「確認時間が減るか」「保留を人が扱えるか」が先の判断材料になる。

| 判断の時点 | 次に選ぶこと |
| --- | --- |
| v1.19相当 | 特徴一覧だけでも価値があるか。価値があれば、その範囲で利用評価へ進む |
| v1.34相当 | 認識・比較の一巡を区切り、形状拡張・検索・編集・業務接続のどれを優先するか |
