# 現在の作業とデータの基準を記録する — v1.16.0

実施日：2026-10-19。**工程別の時間・誤りを記録し、未測定を保持して集計するPython API・CLIを実装した。現場の作業時間・手作業の誤り率はまだ測定していない。** v1.16の計測機能は実装したが、利用者・実帳票による基準測定は未完了である。

## 何を測るための版か

v1.15で固定した[穴情報→既存帳票の業務定義](cad-workflow-definition.md)に対して、現在の手作業を比較基準として記録する。CADで形状・寸法を確認し、転記し、チェックする作業に加え、入力整備・正解付け・設定・説明・更新も分けて記録する。

研究仮説は「少量の設定サンプルから適用範囲を判断できるか」「必要な確認を減らせるか」のままである。今回はその効果・新規性を評価した研究ではない。比較する基準作業が未測定のまま、処理秒数だけを根拠に業務上の優位を主張しない。

## 実装した記録方法

[workflow_baseline.py](../src/research_notes/workflow_baseline.py)と`research-workflow-baseline`を追加した。1セッションは1人・1方法・固定した部品順とし、業務定義・部品manifestの内容とSHA-256を保存する。利用ツールと帳票の参照、匿名の作業者参照も記録する。

| 記録 | 方法と意味 |
| --- | --- |
| 共通作業 | 入力整備、独立した正解付け、設定、説明/習熟、更新 |
| 手作業の工程 | 入力確認、CAD/ファイルを開く、形状・寸法確認、転記、最終チェック、訂正、再実行 |
| 抽出＋全件確認の工程 | 入力確認、抽出、全件確認、転記、最終チェック、訂正、再実行。別セッションで記録 |
| 時間の根拠 | その場の単調時計によるタイマー、外部ストップウォッチの記録、明示した合成値を区別 |
| 未完了の作業 | 途中の時間も保存し、同じ工程の続きへ合算。完了するまで総時間はnull |
| 不要な工程 | 理由付きで明示。未測定・実測0秒とは別にする |
| 品質 | 独立した正解の範囲・出所、確認項目数、誤り、見逃し、誤った完了判定を記録 |

タイマーは中断/再開に対応する。部品全体の正解がない場合は、部分確認から全体の見逃し0を断定できない。認識器の自己出力を独立した正解として扱わない。既知の確認値の小計と全体値を分け、未確認が残る全体値はnullとする。計画した部品は分母から落とさない。

JSONは機械処理用、Markdownは工程・不足箇所を見る表として出力する。記録の完全性は業務成功・採否とは区別する。品質の値自体は利用者が独立照合して入力する方式で、CADや帳票を自動採点したり、観測の真実性を認証したりはしない。

## 今回の確認

### 計算と誤った記録の検証

[合成の計画](../fixtures/cad-workflow-baseline/control-plan.json)に、準備180秒、部品作業60秒/100秒、対象なし3工程、誤り項目1・見逃し1・誤った完了1という**架空の値**を用意した。総時間340秒と各件数が残ることを確認した。合成記録は、全欄が揃っていても利用者の実測・現場基準の完成とは表示しない。

二重計上、負値・真偽値の時間、合成値の実測扱い、未計測の0扱い、部分/不明な正解からの全体無誤り、認識器を正解とする記録、正解数・ハッシュの矛盾など、**12種類の不整合を拒否**した。タイマーの中断除外・未完了保存/合算、更新競合、CLI/Pythonの出力もテストした。

[空の7入力記録](../results/cad-workflow-baseline/unmeasured-session.json)は54工程が未記録で、[集計](../results/cad-workflow-baseline/unmeasured-report.json)の総時間と全体の誤り件数はnullである。知らない値を0とすることで、速く・正確に見せないことを確認した。

### 既存データの内訳と機械処理

[v1.15の固定入力](../fixtures/cad-workflow-contract/reference-cases.json)を再利用し、入力ハッシュを確認して既存の抽出を各2回実行した。出力は繰返しで一致した。認識処理は変更していない。

| 対象 | 件数 | 意味 |
| --- | --- | --- |
| 全入力 | 7 | 開発用の既知入力。新しい未見評価セットではない |
| STEP入力 | 6 | 合成部品5、公開ブラケット1 |
| 読込拒否用の文字列 | 1 | 幾何形状の正解や0穴を割り当てない |
| STEPの全体数に独立した正解あり | 5 | 穴なし、貫通、平底止まり、平行移動、丸穴/長孔混在 |
| STEPの全体数が不明 | 1 | 公開ブラケット。丸穴5・長孔6の部分結果を全体正解にしない |
| 現行処理の状態 | complete 4 / partial 2 / rejected 1 | 混在板はレシピで全体数2でも、処理は全体の確定を保留する |
| 由来系列 | 3 | 合成板系列、公開ブラケット、非STEP。板の変形例を別の未見系列にしない |

各実行の`extraction_seconds`、入力バイト数、出力SHA-256、実行環境を[結果](../results/cad-workflow-baseline/results.json)へ保存した。これは機械による抽出時間で、CADを人が操作した時間・転記時間ではない。機械処理時間と合成時間を、利用者の実測記録へ混ぜない。

## 測定できていないこと

| 項目 | 現在の状態 |
| --- | --- |
| 実際の利用者によるCAD確認・転記・チェック | 未測定 |
| 手作業の誤り率・訂正/再実行時間 | 未測定 |
| 入力整備・正解付け・設定/説明の実作業 | 未測定 |
| 実際の顧客帳票と品質/時間の合意 | 未提供・未合意 |
| 同じ品質での総工数削減・採否 | 未評価 |

現場測定では、作業順・習熟・繰返し・中断の扱いと共通費の配賦を決め、独立した正解を用意して実測する。正解付け等は内訳を残し、同じ方法の総時間へ二重計上しない。共通の評価作業を導入作業と同一視せず、比較する構成で必要な作業・費用の範囲を合意する。今回の単純な工程合計だけで人件費やROIを算出しない。

現場基準の完成を待つ間も、v1.17の既存経路の接続やv1.18の必要項目との対応付けは、研究用入力で進められる。v1.24相当での採否には実作業の比較が必要である。[計画](sme-cad-automation-roadmap.md)ではv1.16を「計測機能実装／現場実測待ち」と記録する。
