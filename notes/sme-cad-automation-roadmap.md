# 中小企業向けCAD周辺業務の自動化：研究ゴールとv1.15以降の計画

更新日：2026-10-19。現行実装はv1.14.0。以下は新しい計画案であり、実装済みの版・性能・顧客導入実績を示すものではない。

## 今回のゴール

**少量のCADサンプルと実際の業務条件から、自動処理に任せられる範囲と人の確認が必要な範囲を見極め、一つの業務を小規模なローカルツールへ接続し、準備・確認・修正を含む総作業時間の削減を実証する。**

研究の対象は、Inefficiency Labが想定する製造・設計業務の「診断」「技術PoC」「小規模開発」を支える判断・導入方法である。特定の加工会社に限定せず、製造業からの直接相談と、CAD周辺案件を扱うSIer・開発会社の技術検証・部分開発を想定する。[サービスページ][services]

前回の[100項目ロードマップ](brep-recognition-roadmap-100.md)は技術候補の記録として保持するが、実装順・研究ゴールとしては本案に置き換える。最初から認識種類を増やし続けたり、全カーネルを統合したりする工程は設けない。必要な既存認識・照会・比較を再利用し、実業務の成立を妨げる不足だけを対象にする。

## 中小企業向けの優位を、何で確かめるか

以下は優位性の仮説である。「安価」「短期導入」「少数データで成立」を達成済みとは主張しない。顧客の業務、既存ツール、導入・運用条件と比較して測る。

| 狙う優位 | 提供したい状態 | 測るもの |
| --- | --- | --- |
| 少ない準備で始められる | 全社のデータ整備を前提にせず、一業務のサンプル・帳票から評価する | 必要なサンプル/正解付けの量、入力整備・設定・説明にかかった時間 |
| 既存業務へ接続しやすい | 普段のExcel/CSVと確認手順を活用する | 帳票への接続時間、二重入力・追加の操作・運用変更の量 |
| 人の確認を含めて省力化する | 自動取得できたことと、業務として確認が済んだことを区別する | 操作・確認・訂正・再実行を含む一回の時間、誤取得・見逃し・保留 |
| 社内の実行条件に合わせる | ローカル実行を選べる構成を確認する | 導入・更新の手順、通信要件、必要なCAD/ライセンス、実行資源 |
| 小規模開発として繰り返し提供する | 処理本体を再利用し、必要な列・条件・例外を案件ごとに調整する | 二つ目の帳票/案件への設定・改修時間、保守負担 |

ローカル処理やExcel出力だけを新規性の根拠にはしない。CAD比較・レポートは[Kubotekの既存製品][validate]に、形状/仕様解析や業務データとの関連付けは[CADDiの製品説明][caddi]にもある。ここでの製品情報は提供元による説明であり、こちらで精度・導入費用・使い勝手を実測した結果ではない。既存製品より優れると判断したものでもない。

## 学術的な研究課題と、事業上の優位を分ける

| 区分 | 問い | 今回の扱い |
| --- | --- | --- |
| 既存技術の利用 | B-Repから穴・長孔等を取得できるか | 既存APIを先に使う。抽出機能そのものを新規の成果として数えない |
| 研究仮説A | 少数サンプルから決めた適用条件で、未見部品の業務成立・要確認をどこまで予測できるか | 入力表現・形状・必要項目の依存関係を用いる方法を、単純なサンプル成功率等と比較する |
| 研究仮説B | 形状認識の不確かさと業務条件を使い、必要な人の確認を減らせるか | 項目の自動確定誤りだけでなく、確認件数・時間・業務全体の見逃しを同時に測る |
| 事業上の仮説 | 一業務に絞った導入が、現在の手作業や使える既存ツールより有利か | 準備・教育・確認・訂正・更新まで含め、同じ品質条件で比較する |

A/Bは新規性を調べる候補であり、未発表・世界初と確認できた手法ではない。少量データの性能予測、保留や確認優先度にも先行研究があることを前提に、CAD業務でどこに未解決の差があるかを追加調査する。差が見つからなくても、既存手法を使った導入上の優位を実測する研究は継続できる。

例えば[学習曲線を用いた意思決定の調査][learning-curves]や、誤りと自動判定する割合を扱う[選択的分類の研究][selective-classification]がある。これらの問題設定そのものを新規と主張せず、CAD業務の必要項目・欠落情報・人の確認との関係を比較対象にする。これらの論文の性能や保証を、本研究のB-Repへ移して主張するものではない。新しい学習モデルの開発も必須にせず、条件表・依存関係・統計評価等で成立する方法を先に検討する。

## 最初の一業務

**受領したCAD/B-Repから必要な穴情報を取得し、既存のExcel一覧へ転記し、確認が残る箇所を根拠付きで引き渡す。**

既存の穴・長孔一覧、保留説明、Python/CLI・画面の成果を再利用する。SMLib・SolidCraft・ClassCAD等は[前回の調査](brep-native-recognition-strategy.md)に基づく利用候補とし、現在動く経路を含めて、必要な入力・出力・実行条件を満たす最小構成を選ぶ。3基盤の一括対応やSMLibへの移植を先行条件にはしない。

| 項目 | 最初に決める範囲 |
| --- | --- |
| 入力 | 対応する受領STEP、または直接扱えるネイティブB-Rep/文書。単位・座標系・部品範囲を明示する |
| 欲しい結果 | 業務で必要な径・位置・方向・貫通長等。深さや位置の基準、必須列・任意列、穴数の意味を合意する |
| 判定 | 自動取得して使える、部分結果を人が確認、必要情報/対応経路が不足、を区別する |
| 出力 | 既存帳票に合わせた一覧、要確認項目と理由、参照可能な面/部品、処理条件の記録 |
| 比較する相手 | 現在のCAD確認・Excel転記、利用できる既存ツール/単純な抽出CSV運用 |

**「穴を何個か取得できた」と「部品の穴一覧が完成した」は別の状態である。** 全体穴数が不明なのに業務完了と判定した場合も誤りとして扱う。現在の公開ブラケットの丸穴5・長孔6という部分結果を、全穴の取得や業務成立の正解に置き換えない。

B-Repだけに含まれない材質・公差・ねじ指示・加工条件等は、入力不足として返す。形から推測して必須帳票欄を埋めない。履歴・注記・図面等を使う場合は出所を残し、最初からPDF読解を必須機能として追加しない。

## 評価方法と最初の区切り

最初の到達点を**v1.24相当の業務PoC**とする。v1.19相当で小さな処理の一巡を作り、以後は認識種類より未見データと人の作業を測る。結果は採用・条件付き採用・追加検証・見送りのいずれでもよい。見送りとなった場合は、実用上の優位を達成したとは扱わない。

| 評価すること | 方法 |
| --- | --- |
| 誤取得・見逃し・保留 | 人が確認した正解・既知の設計値を基準とする。認識器同士の一致だけを正解にしない。未知項目の分母を除外して高い自動化率を出さない |
| 業務の成立 | 必須項目が揃い、未処理の必須確認が残っていないかを判定する。部品単位・項目単位を分けて報告する |
| 少数サンプルからの予測 | 例えば3/5/10/20件の設定サンプルで比較し、別部品群で成立/要確認の予測を評価する。件数は実験案で、最低保証数ではない |
| データの分離 | 同一部品の別出力・微小変形・改訂を設定用と評価用へ無造作に分けない。部品系列や由来を単位に分離する |
| 未知の条件 | 観測のない形状・表現・必須項目は、不明や追加評価を返す。少数の成功から全データへ一般化しない |
| 比較方法 | 全て手作業、単純な抽出/一律確認、提案する適用条件/確認支援を同じ対象で比較する。順序・習熟・繰返しによる時間差にも注意する |
| 工数 | 初期の入力整備・設定・導入・説明と、毎回の実行・確認・訂正・再実行を分ける。初期工数＋実行回数×一回の工数も比較する |
| 採否 | 許容する誤り・見逃し、必要な時間短縮・導入負担の基準を評価前に決める。未達や不明も報告する |

公開データ・合成データで方法を先に検証できるが、業務データと利用者による測定がない段階では「中小企業で効果を実証した」とはしない。顧客データの利用条件・共有範囲は個別に確認し、この計画自体は外部への連絡・データ送信・サイト変更を実行しない。

## v1.15.0からの計画案

最初の10項目を一業務のPoCまでの候補とする。v1.25以降は効果が確認できた範囲を選んで進め、版番号のために一項目ずつ実装する必要はない。以下に新しい認識器や性能予測器が実装済みという意味はない。

### 直近：一業務で導入負担と確認工数を測る

| 版（案） | 研究・開発 | 到達点・判断材料 |
| --- | --- | --- |
| **v1.15.0** | 対象業務・先行手法・採否基準を固定 | 穴情報→既存帳票の一業務について、必須項目・穴数の意味・人の確認・正解の作り方を決め、研究仮説と比較対象を先行調査で絞る |
| v1.16.0 | 現在の作業とデータの基準を測定 | CAD確認・転記・チェックの時間と誤り、入力整備・正解付けの負担を記録する |
| v1.17.0 | 既存の認識・照会を最小構成で接続 | 現行経路や必要な既存APIを利用し、入力の特徴・実行条件・項目の出所を取得する |
| v1.18.0 | 業務に対する自動化可否を説明 | 取得可能・要確認・情報不足を必要項目と対応付け、部分抽出を完了扱いにしない |
| **v1.19.0** | 既存帳票へ出力する小さな一巡 | 受領CAD→抽出→帳票→要確認一覧をローカルで動かす。書式の維持等は合意範囲に限定 |
| v1.20.0 | 人の確認を支援して工数を測定 | 理由・形状参照・必須項目の依存関係を示し、既存の保留説明を再利用して確認時間を測る |
| v1.21.0 | 未見部品で業務の成立を評価 | 別部品群で誤取得・見逃し・保留・業務完了判定を測る |
| v1.22.0 | 少数サンプルからの適用範囲を予測 | サンプル数を変え、単純な成功率と提案方法の予測を比較。不明条件への保留も評価する |
| v1.23.0 | 導入・設定・更新の負担を測定 | 初期準備、帳票設定、説明、通信/ライセンス条件、修正時の作業を記録する |
| **v1.24.0** | **最初の業務PoCを評価** | **同じ品質条件で総工数を比較し、採用・限定採用・追加検証・見送りを判断する** |

### 条件付き：改訂後に再確認すべき作業へ広げる

| 版（案） | 研究・開発 | 到達点・判断材料 |
| --- | --- | --- |
| v1.25.0 | 会社固有の確認条件を登録 | 必要な寸法・社内基準・帳票の依存関係を少量のルールとして表す。登録・保守の手間も測る |
| v1.26.0 | 新旧CADの変更を業務項目へ接続 | 既存の対応付け・幾何差分を評価し、変更した形状と影響する帳票項目を結び付ける |
| v1.27.0 | 再確認する項目と不足情報を抽出 | 変更・不確かな対応・未登録条件から確認候補を返し、未確認を自動的に影響なしにしない |
| v1.28.0 | 確認の優先順位を比較評価 | 全件確認・差分だけの確認・提案する確認順序を比較し、重要項目の見逃しと時間を測る |
| v1.29.0 | 入力表現・修復・閾値の違いを検証 | 利用する処理の差で業務上の結論が変わる条件を調べ、保留・再評価へ返す |
| v1.30.0 | 改訂確認のPoCを評価 | 新旧データと現場の確認結果で、準備・再確認・訂正を含む工数と品質を評価する |

### 条件付き：別案件でも使える範囲を固定する

| 版（案） | 研究・開発 | 到達点・判断材料 |
| --- | --- | --- |
| v1.31.0 | 別帳票・別案件への適用を評価 | 処理本体を再利用できる範囲と、設定/個別開発が必要な範囲、その工数を測る |
| v1.32.0 | SIer・開発会社向けの接続を整理 | Python/CLI/API、結果・保留・出所の定義と再現条件をまとめ、既存システムから利用可能にする |
| v1.33.0 | 採用構成の導入・異常時運用を確認 | 必要な環境だけで導入・更新・失敗からの再実行を確認し、保守範囲を説明する |
| v1.34.0 | 研究結果と提供可能範囲を固定 | 誤判断・工数・準備量を既存方法と比較し、診断/PoC/小規模開発で再利用する成果物を揃える |

## サービスへのつながり

| サービス | 研究成果をどう使うか |
| --- | --- |
| 自動化診断 | 業務に必要な項目・現データの不足・必要な人の確認を整理し、実現方法と評価範囲を決める |
| 技術PoC | 顧客データと未見データで、予測・誤取得・見逃し・保留・総工数を検証し、採否の材料を出す |
| 小規模開発 | 採用範囲に絞ったローカル処理・既存帳票への出力・例外確認・操作手順を実装する |
| SIer・開発会社の支援 | データ調査、比較評価、抽出や出力等の部分開発として接続する |

診断・PoC・開発は必須の順番ではない。既に範囲が決まっている案件は、その段階から利用できる構成にする。HPの実装・更新は本リポジトリの計画に含めない。

## 今回変更するもの・保持するもの

研究のゴール・優先順位と文書索引を変更する。現在の解析・認識・比較のコード、版、依存関係、過去の検証値は変更しない。以前の機能候補は削除せず、業務上の不足が確認できた際に選ぶ。

前回のSMLib等の調査は利用可能な手段の証拠として残す。独自認識器の全面的な移植、形状認識の網羅、部分形状検索の一般化を、新しい最初のゴールにはしない。

この計画では学術的新規性も中小企業向けの優位性も未達成である。どちらが得られたかは、先行研究・既存手法との比較と、対象業務での測定を通して判断する。
