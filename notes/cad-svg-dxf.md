## Research Question

同じFreeCAD図面から出力したSVGとDXFを別々に読み、
寸法・生成ソリッド・寸法変更後のソリッド・保留理由は一致するか。
SVGの座標変換、曲線近似、回転文字を扱っても、根拠のない寸法補完を避けられるか。

対象は前回と同じ自作の矩形板（無孔／1丸穴）の開発用対照。
「実CADの出力」であり、第三者の実務図面や未知形状の評価ではない。

## Source Review / Method Selection

| 一次資料 | 確認内容 | 実装・実行した範囲 |
|---|---|---|
| [W3C SVG座標系](https://www.w3.org/TR/SVG11/coords.html#TransformAttribute) | viewBox、親子の座標変換、変換の積 | mm用紙への正規化、matrix/translate/scale/rotateの合成 |
| [W3C SVGパス](https://www.w3.org/TR/SVG11/paths.html#PathDataCubicBezierCommands) | 直線、三次ベジェ、絶対／相対パス | M/L/H/V/C/Z。円を表す4区間の三次ベジェのみ形状解釈 |
| [W3C SVG文字](https://www.w3.org/TR/SVG11/text.html#TextElement) | x/y基点と文字への座標変換 | XML文字列、変換後のベースライン・方向。OCRなし |
| [前回のFreeCAD実測](cad-drawing-exports.md) | TechDraw1.1.4の実SVG/DXF表現、出所・ライセンス | 元ファイルを変更せず使用。今回CAD再出力は不要 |

仕様上存在する機能と実装範囲を区別する。
非一様変換、反転、skew、任意の円弧／スプライン、CSSクラス、クリップ、マスク、
use、tspan、文字アウトライン、画像は今回の対応範囲外。
SVG一般への完全対応は主張しない。

方式C（非AIベクター解析）を継続。新しい依存は追加していない。
OCCT、編集用フィーチャーモデル、STEP入出力・計測・穴認識・HLRを再利用。
VLM、OCR、外部API、GPU、学習との比較は未実施。

## Controlled Experiment

元の8文書設定を使い、誤投影法の対照を両形式に用意した。
9条件×2形式×2反復 = **36試行**。
派生条件と反復を独立した部品数には数えない。

| 条件 | SVG | DXF |
|---|---|---|
| 無孔板、1穴板、小数寸法、縮尺1.5、第一角法 | 各2回、復元・編集を照合 | 各2回、復元・編集を照合 |
| 穴X寸法なし | hole_position_missing | 同左 |
| 貫通指示なし | hole_extent_ambiguous | 同左 |
| ±0.1の公差表記 | unsupported_annotation | 同左 |
| 第三角法の図面へ第一角法を指定 | projection_layout_conflict | 同左 |

人が与えた情報: mm、矩形板＋分離したZ貫通丸穴という形状クラス、
投影法、左下基準の規約、ビュー対応。
DXFでは既存のレイヤー名を選ぶ。
SVGでは **DrawingContentグループと、正面・平面・右側面の外形パス3本を人が指定**する。
SVG原本にはビュー名の意味情報がないため、この追加の手動選択を明記する。
パス参照は選択グループ内の0始まりpath番号。数値寸法・縮尺・元CADは渡さない。

[選択の固定スクリプト](../experiments/prepare_cad_svg_pairs.py)には目視で確認した参照を保存。
任意ファイルの要素順からビューを自動推定する処理ではない。
要素順変更時には人の参照も追従させるテストで、意味が順番へ依存しないことを確認する。

復元関数はバイト列とcontextだけを受け取る。
各形式を別プロセスで実行し、SVG側からDXFを読まない。
生成コードを実行してから評価側が正解STEP・設計値を読む。
この分離はAPI・処理順の分離であり、OSサンドボックスではない。

## Method / 実出力から学んだこと

1. 用紙のmm/viewBoxを読み、親から子へ座標行列を合成する。
2. 選択した外形と実際の輪郭線が対応するか確認する。
3. 塗り・線の重複は照合したうえで整理。隠れ線は破線属性を確認する。
4. 線寸法は寸法線と2本の補助線の交点、三角矢印、外形頂点／穴中心を関連付ける。
5. 文字は変換後のベースラインの向きと距離を照合する。数値の近さだけで対応付けない。
6. 径寸法は円の対向点にある矢印と、その2点を通る引出線・THRU文字を照合する。
7. 表示寸法を設計値として使い、輪郭・円・隠れ線・投影配置で整合性を確認する。
8. 既存のフィーチャーモデルから編集用PythonとSTEPを生成する。

小数寸法の厚さ6.5 mmでは、FreeCADが矢印を外向きにし、寸法線を延長していた。
線端をそのまま測定端とする試作では dimension_target_ambiguous になった。
最終処理は補助線との交点を測定端とし、内向き／外向きの両矢印配置を確認する。
この改善は同じ開発用サンプルを見て行ったもので、ホールドアウト精度ではない。

SVGの円は4つの四分円ベジェで、数学的な真円ではない。
端点、中心、半径、接線制御点を円近似の形と照合する。
任意曲線を円へ強制的に置き換えない。
正確なCAD半径は径の表示値から取り、元のベジェ曲線との差を別に保存する。

グラフィックスの関連付け許容値は **用紙上0.002 mm**。
実SVGの丸めで、寸法線と矢印位置に最大約0.0005 mmのずれがあったため。
形状・注記照合はこの値を図面縮尺でモデル座標へ換算する。
CAD寸法誤差の1e-6 mm、再投影サンプル距離0.02 mmとは別の値で、
どれも製造上の合格公差ではない。

## Evaluation

| 評価 | 観測 |
|---|---|
| 正例5条件×2形式×2回 | 20/20でコード実行・有効な単一ソリッド・STEP再読込・寸法／形状／編集を通過 |
| 負例4条件×2形式×2回 | 16/16で理由付き保留。候補の誤確定0 |
| SVG対DXFの抽出パラメータ最大差 | 0 mm（外形、穴径、位置） |
| SVG対DXFの復元STEP体積IoU | 5組とも1.0、材料の対称差0 mm³ |
| SVG対DXFの編集後STEP体積IoU | 5組とも1.0、材料の対称差0 mm³ |
| 保留理由の一致 | 4組とも一致 |
| 正解設計値に対する穴径・XY・貫通長の最大誤差 | 0 mm |
| 外形のSTEP計測最大誤差 | 約2.0e-7 mm（境界ボックス許容差を含む） |
| SVG元ベジェ輪郭とHLRの最大サンプル残差 | 約0.00167841 mm |
| DXF輪郭とHLRの最大サンプル残差 | 約7.11e-15 mm |

編集は幅+5 mm、厚さ+2 mm、穴があれば径とXを各+1 mm。
生成PythonのPARAMETERSを変更して再実行する。
元作者の操作履歴の復元ではなく、条件付き候補の編集可能なレシピ。

SVGの元曲線は129点/ベジェ区間、HLRは曲線129点でサンプルする。
双方向の点→折れ線距離なので、連続曲線の厳密な最大偏差ではない。
ベジェ自体の真円からの偏差と、HLR折れ線の離散化誤差を含む。
円へ近似した後の輪郭比較だけではこの誤差が見えなくなるため、
raw_drawing_polylines_mmとraw_projectionを独立に保存した。

正解STEPはFreeCAD/OCCT7.8.1、復元・照合はcadquery-ocp7.9.3.1.1。
経路と版は違うが同じカーネル系列。SVG/DXFも同じ図面の出力なので
形式間一致だけでは設計の正しさを証明しない。
別保存の既知設計値・解析式・元STEPとの評価を継続する。

## Interpretation / Limitations

今回の5条件では、SVGもDXFも同じ寸法と編集可能な形状に到達した。
ただしSVGには寸法エンティティの意味が残らず、図形の対応付けが必要だった。
寸法文字がXMLテキストとして残り、ビューを人が選び、
限定した板形状と寸法表記を使う条件で成立した結果である。

任意の曲線、楕円、円弧コマンド、止まり穴、断面図、複雑な部品、
GD&T、公差解釈、複数尺度混在、スキャン、文字アウトライン化は未検証／未対応。
線種の全可視性や文字の字形境界は評価しない。
図面の一意な3D解釈、完全自動化、実務精度、新規性、工数削減は未実証。
