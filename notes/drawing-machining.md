# 交差形状・穴の種類・寸法表記の拡張

2026-10-23 JST（実行記録は2026-10-22 UTC）。独立した2D→CAD探索。
前回計画の5・6・7を実装した。リリース番号と既存業務ロードマップは変更していない。

**ポケットの底を貫通する穴、平底の止まり穴、段付き貫通穴、側面穴を追加し、
連鎖寸法・同径穴の数量・数値の寸法公差を読み取れるようにした。**
[結果HTML](../results/drawing-machining/report.html)に入力図面、復元／変更後3D、寸法、公差、保留理由をまとめた。

依頼に従い、**テストコードの追加とpytest等のテストスイート実行は行っていない**。
実行したのは、結果を残すための自作FreeCAD図面による復元実験である。
以下は開発用の例を各1回実行した観測であり、回帰テスト通過、未知図面の成功率、
一般的な頑健性を示すものではない。前回の1,573テスト成功を今回の変更に引き継いで主張しない。

## Research Question

1. 穴がポケット内を貫通する場合、重複した除去体積を考慮して形状を復元・編集できるか。
2. 穴径・位置に加えて、深さ・軸・段付き構造を可視の寸法注記と投影から取得できるか。
3. 基準から直接記載されていない位置を連鎖寸法から求め、公称値と数値公差を区別できるか。

## Source Review / Method Selection

[前回の複合形状研究](drawing-composites.md)の寸法解析、SVG正規化、OCCTの
Boolean・HLR・STEP入出力・プレビューを再利用した。
新しい `drawing_machining` と版を分けた寸法解析器を追加し、従来の凍結済み復元ソースは編集していない。
FreeCAD 1.1.4で作者側形状・図面・元STEP・編集後STEPを作り、復元にはOCP 7.9.3.1.1を使う。
新しいCADカーネル、外部AI API、GPU、大規模依存は導入していない。
ソフトウェアの出所・ライセンスは[既存の実CAD出力記録](../docs/drawing-generalization.md)を継承する。

## Method / 実装した範囲

| 対象 | 実装したこと | 制限 |
|---|---|---|
| 交差形状 | 矩形ポケット内に完全に収まるZ方向の貫通穴をBooleanで切削 | ポケット壁への食い込み、交差する側面穴、穴同士の交差は対象外 |
| 止まり穴 | 径・中心位置・`DEPTH`の公称深さを取得し、進入面の候補を比較 | 平底の円筒。ドリル先端の円錐を持たない |
| 段付き穴 | 同心の小径THRUと大径DEPTHを1段の座ぐり付き貫通穴としてまとめる | 多段穴、両径とも止まり、皿穴は対象外 |
| 側面穴 | 円が現れるビューから軸を対応づけ、横方向の円筒切削を作る | 今回の実行例はX方向。Y方向・負側進入はコードの候補にあるが未実行 |
| 連鎖寸法 | 参照点をつなぐ符号付き寸法グラフを作り、板の基準から位置を導く | 各投影面の軸方向寸法。任意角度・寸法連鎖公差解析ではない |
| 同径穴の数量 | 1つの径指示を、同じビュー内の一致する径の円へ対応づける | 最大3個。複数の穴群が同径で混在する一般的なグループ解釈は未対応 |
| 寸法公差 | `±0.2`、`+0.2/-0.1`等の数値偏差を公称値と分けて保存 | H7等のはめあい、幾何公差、一般公差、深さ公差、上下2段組表記は未対応 |

公差はB-Repの幾何許容値や図面不整合を許す閾値へ流用しない。
形状は公称寸法で生成し、元文字・公称値・上下偏差・寸法IDをモデルJSONに残す。
編集後の公差の妥当性、製造合否、最悪値・統計的な公差積上げは判断しない。

## Controlled Experiment / 今回実行した開発例

自作10ページをFreeCAD TechDrawからSVG／DXFへ書き出した。
そのうち7ページが今回の形状・寸法表記の例で、3ページは深さ不足・数量矛盾・未対応表記を含む。
各20入力を1回実行した。未調整集合や繰り返し安定性の評価は実施していない。

人が指定するのはmm、第三角法、3ビューの対応と対象形状の範囲。
穴径・位置・深さ・公差をcontextで渡さず、実際の図面の寸法から取得する。
作者仕様JSON、FCStd、正解STEPは復元ワーカーへ入力しない。
別プロセスには図面と非数値contextだけを中立名でコピーする。これは入力経路の分離でありOSの隔離ではない。

作者側と復元側は別の形状生成実装を持つが、どちらもOCCT系である。
別のCADカーネルや別の作者による実務図面の独立評価ではない。
書き出し時の初期実装では変数名衝突による処理停止があり、作者側マクロを修正後に全ページを出力した。
固定した入力を用いた最初の完了実行を保存しており、結果を見て復元処理を再調整した反復は行っていない。

| 開発図面 | SVG | DXF |
|---|---|---|
| ポケットの底を貫通する穴 | 復元・編集後一致 | 加工方向が複数残り保留 |
| 上面の平底止まり穴 | 復元・編集後一致 | 復元・編集後一致 |
| 座ぐり付き貫通穴 | 復元・編集後一致 | 復元・編集後一致 |
| 側面の平底止まり穴 | 復元・編集後一致 | 復元・編集後一致 |
| 側面の貫通穴 | 復元・編集後一致 | 復元・編集後一致 |
| 連鎖寸法＋同径2穴 | 復元・編集後一致 | 復元・編集後一致 |
| 数値公差付き止まり穴 | 復元・編集後一致、公差保存 | 復元・編集後一致、公差保存 |
| 深さ指示なし | `hole_extent_ambiguous`で保留 | 同左 |
| 2穴に対して3個の数量指示 | `quantity_conflict`で保留 | 同左 |
| `H7`を含む指示 | `unsupported_annotation`で保留 | 同左 |

20入力のうち13入力で候補を生成し、7入力を保留した。
候補13入力で作者側の設計パラメータが一致し、元形状・編集後とも有効な単一B-RepとSTEP再読込を観測した。
正解STEPとの体積IoUの最小値は1.0、外形差の最大値は0 mm。
解析式との体積差の最大値は2.04e-10 mm³、面積差は1.50e-10 mm²、
元図面への再投影の最大サンプル残差は0.003355 mmだった。
これは実行例の数値照合であり、テストスイートや未知図面の性能評価とは区別する。

寸法変更は、板幅+4 mm・板厚+2 mm、ポケット深さ+1 mm、穴径+0.5 mm、
止まり穴深さ+1 mm、座ぐり径+0.5 mm・座ぐり深さ+1 mm。
同じ変更を作者側でも独立に行い、編集後STEPを比較した。元CAD作者の操作履歴を復元したものではない。

### 具体的に読めた寸法

- 連鎖例の第2穴：Xは20＋38＝58 mm、Yは18＋24＝42 mm。
  どの寸法IDをたどったかを `bindings` に保存した。
- `2 x 6 THRU`：2つの径6 mmの円に適用。2円しかない `3 x 6 THRU` は保留した。
- `10 +0.2/-0.1 DEPTH 8`：公称径10 mm、下側偏差−0.1 mm、上側偏差＋0.2 mm、深さ8 mmを分離した。
- 板の `72 ±0.2`：幅72 mmで形状を作り、±0.2 mmを別項目として保存した。

### DXFで復元できた理由と、残る保留

今回もDXFの可視線／隠れ線を区別できるとは扱っていない。
ただし実深さ8 mmの止まり穴では、上から深さ8 mmと下から深さ8 mmで内部平面の位置が異なる。
三面図の輪郭との整合で候補が1つになった場合は採用できる。
厚さの半分など、同じ輪郭を説明する候補が複数なら保留する設計で、その条件の実行例は今回未追加。
ポケットの上面参照寸法には上下の別解が残ったため、今回のDXF例は保留した。
前回の線種不足を一般的に解決したという主張ではない。

## Interpretation / Limitations

前計画5〜7について、限定した実装と保存済みの実行例まで進めた。
テストは追加・実行しておらず、既存機能の回帰、例外全般、数値スケール・配置の頑健性は未確認。
新しい未調整集合、第一角法、Y方向側面穴、負側進入、複数の公差表記・数量群の混在、
図面品質劣化、顧客図面、OCR／AI方式、ネイティブWindowsでの実行も未評価。
公差を保持することと、その意味を製造要件として完全に理解することは別である。
