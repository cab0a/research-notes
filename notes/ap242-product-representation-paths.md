# AP242 Product and Representation Paths

## 日本語概要

このノートは、STEP Part 21の物理参照graphから、AP242で製品定義を形状表現、表現項目、座標次元、単位へ結ぶ制御された意味経路を抽出できるかを検証します。14件の合成fixtureは3件受理・8件隔離・3件拒否となり、解決した5経路、59参照関係、9表現項目、15単位をsource span付きで記録しました。形状関連付けがない製品定義や未対応schemaを破損と断定せず、AP242完全適合、assembly occurrence、変換合成、単位換算、B-rep幾何評価は主張しません。疑問点、方法、結果、限界は以下の英語本文に示します。

## English Summary

This study resolves a controlled, source-linked path from AP242 product
definitions to shape representations, direct representation items, geometric
context, and assigned SI units. Fourteen synthetic fixtures exercise resolved,
optional, unsupported, invalid, and resource-bounded routes. The resolver
preserves the distinction between physical reference occurrences and the
schema-derived roles assigned to those occurrences.

## Research Question

Can the generic Part 21 reference graph support a defensible AP242
product-to-representation query without treating entity-name coincidence as
application semantics or treating absent optional geometry as file corruption?

The controlled path is:

```text
PRODUCT
  <- PRODUCT_DEFINITION_FORMATION
  <- PRODUCT_DEFINITION
  <- PRODUCT_DEFINITION_SHAPE
  <- SHAPE_DEFINITION_REPRESENTATION
  -> SHAPE_REPRESENTATION
  -> direct representation items
  -> REPRESENTATION_CONTEXT
     + GEOMETRIC_REPRESENTATION_CONTEXT
     + GLOBAL_UNIT_ASSIGNED_CONTEXT
```

## Background

Part 21 local references establish physical links between encoded records, but
they do not name the role of each link. The generic graph in v0.28.0 can answer
which entity references which occurrence ID. It cannot, by itself, determine
whether that edge means product formation, shape definition, representation
selection, or unit assignment.

The public ISO SMRL pages define the relevant contracts. `PRODUCT` identifies
a product; `PRODUCT_DEFINITION_FORMATION` associates a version or formation
with that product; and `PRODUCT_DEFINITION` identifies a view of that
formation. `PRODUCT_DEFINITION_SHAPE` specializes property definition for a
product-related shape, while `SHAPE_DEFINITION_REPRESENTATION` associates that
definition with a shape representation. A representation contains a name, a
set of representation items, and a representation context. Geometric context
adds coordinate-space dimension, and a global-unit context assigns units.

An important negative fact follows from these definitions:
`PRODUCT_DEFINITION_SHAPE` does not guarantee that a geometric representation
is encoded. Absence of the later association is therefore a deferred path in
this study, not evidence that the Part 21 file is malformed.

## Method

The resolver first parses the source with the v0.23.0 source-preserving Part 21
model and builds the v0.28.0 directed multigraph. It then applies an explicit
role map for one declared schema identifier:
`AP242_MANAGED_MODEL_BASED_3D_ENGINEERING_MIM_LF`.

For each encoded `PRODUCT_DEFINITION`, it:

1. follows required references to formation, product, and definition context;
2. finds the unique referring `PRODUCT_DEFINITION_SHAPE`;
3. finds each referring `SHAPE_DEFINITION_REPRESENTATION`;
4. validates its selected representation against a small supported subtype set;
5. reads the direct item aggregate and representation context;
6. extracts coordinate-space dimension and explicitly assigned context units;
7. classifies only controlled direct-item roles; and
8. joins every semantic relation back to exactly one physical graph edge,
   parameter path, and source span.

The accepted representation types are `SHAPE_REPRESENTATION`,
`ADVANCED_BREP_SHAPE_REPRESENTATION`,
`FACETED_BREP_SHAPE_REPRESENTATION`, and
`TESSELLATED_SHAPE_REPRESENTATION`. This is an implementation boundary, not a
claim that these four names cover AP242.

The direct-item classifier distinguishes placement, solid model, geometric
item, mapped item, and unclassified. Classification records the entity role;
it does not evaluate geometry or traverse the B-rep owned by a solid.

## Controlled Experiment

All inputs are generated by
[`ap242_path_study.py`](../src/research_notes/ap242_path_study.py). The corpus
contains 14 readable `.step` files and a hash manifest.

| Group | Controlled condition | Expected handling |
| --- | --- | --- |
| Resolved paths | generic shape representation, advanced B-rep root, two representations | accept |
| Optional paths | no product definition, no shape definition, no representation association | quarantine |
| Schema and subset boundaries | AP214 declaration, unsupported representation type, missing units, unclassified item | quarantine |
| Semantic invalidity | wrong target type, unresolved local reference, parameter-count mismatch | reject |
| Resource boundary | two paths with a one-path work budget | quarantine |

The representative model encodes one product, formation, product definition,
shape definition, shape representation, one placement, one block, a 3D
geometric context, and millimetre, radian, and steradian SI units. The advanced
B-rep fixture reuses the independently checked v0.21.0 closed tetrahedron and
exposes its placement and manifold solid as direct representation items. A
separate fixture associates two representations with one product definition
so path multiplicity is observable.

Run the exact experiment with:

```bash
python experiments/run_ap242_product_paths.py
```

Regenerate the committed input corpus only when intentionally changing its
definitions:

```bash
python experiments/run_ap242_product_paths.py \
  --fixture-dir fixtures/ap242-product-paths \
  --refresh-fixtures
```

## Interpretation

The experiment demonstrates the first application-semantic query built over
the generic Part 21 graph. A relation row is more than an adjacency pair: it
records the schema-derived role and the exact encoded reference occurrence
that supports that interpretation. This makes later disagreement inspectable
at the source rather than hiding it behind a reconstructed object graph.

Three distinctions are central:

- A readable physical link is not yet a valid semantic role.
- A missing product-to-shape path can be permitted or outside the controlled
  subset; it is not automatically corrupt.
- Reusing familiar entity names under AP203 or AP214 does not prove that the
  controlled AP242 interpretation is portable to those schemas.

The accepted fixtures establish only that the controlled chain resolved. They
do not establish complete AP242 conformance or geometric validity.

## Failure Modes

- A local reference can resolve physically while targeting the wrong entity
  role. This is rejected.
- A local target can be absent. The graph preserves that occurrence, but the
  semantic query rejects the required path.
- A shape definition can legitimately have no supported representation. The
  query quarantines the missing semantic evidence.
- A representation or direct item can fall outside the controlled subtype
  registry. It is preserved and quarantined instead of guessed.
- Context units can use conversion-based or derived forms not evaluated here.
  They must not be silently treated as SI.
- A product definition can have multiple representation associations. Any
  consumer that selects the first path would lose information.
- Unlimited reverse scans, paths, relations, items, or units could turn a
  semantic query into uncontrolled work. Explicit counters stop that route.

## Practical Guidance

- Keep the generic physical graph immutable and add semantic roles as a
  separate evidence layer.
- Require an exact declared schema before applying an application-specific
  role map.
- Preserve every source edge and parameter path used by a semantic result.
- Treat no-path, unsupported-path, invalid-path, and budget-exhausted outcomes
  separately.
- Carry representation context and units with every extracted shape root.
- Do not call a representation placement an assembly occurrence transform;
  those concepts require a later assembly study.
- Do not convert millimetres, angles, or placements until the complete unit and
  transformation chain is known.

## Limitations

- The resolver is not a complete implementation of ISO 10303-242.
- Only one exact AP242 MIM schema identifier is admitted.
- The controlled entity map is hand-selected; it is not generated from the
  full AP242 EXPRESS schema.
- Subtype closure is not derived from the v0.26.0 EXPRESS resolver.
- The fixtures are synthetic and intentionally small.
- Product contexts are not semantically evaluated.
- Assembly occurrences, representation maps, item-defined transformations,
  and transformation composition are deferred.
- Conversion-based units, derived units, uncertainty, tolerances, and unit
  conversion are deferred.
- Representation items are classified only at the direct root; B-rep
  topology and geometry are not traversed or evaluated.
- No geometry kernel is used, and no area, volume, normal, validity, or visual
  equivalence claim is made.
- `accept` means the controlled path resolved, not that the file is AP242
  conformant, interoperable, complete, safe, or suitable for manufacturing.

## Questions Carried Forward

1. How should product occurrences and reusable representations be modeled
   without confusing definition identity, occurrence identity, and file-local
   entity IDs?
2. Which placement and transformation entities must be composed, and in what
   direction, to place reused components in an assembly?
3. How should mixed SI, conversion-based, and derived units be normalized while
   retaining their source declarations?
4. Can the controlled role map be derived from resolved EXPRESS inheritance
   instead of an entity-name registry?
5. What evidence is required before a resolved representation root may be
   handed to B-rep topology and kernel-evaluated geometry stages?

These questions define the natural next study: assembly, reuse, placement, and
units.
